# 자동 데이터베이스 백업 — v2026.09.12.1

날짜: 2026-09-12
상태: 구현 브랜치 / 클러스터 테스트 대기
브랜치: `feat/v2026.09.12.1-auto-db-backup`

## 목표

운영 PostgreSQL 백업을 단순히 덤프 파일을 생성하는 수준에서 끝내지 않고, 저장된 백업 산출물이 실제로 검증되고 복구 가능한 상태인지 자동으로 확인한다. 저장 백업은 SHA-256 검증, PostgreSQL 아카이브 구조 검사, 최신성 확인, 격리된 복구 DB에 대한 실제 복원까지 통과해야 한다.

## 변경 사항

1. `wdmvp-db-backup`은 기존처럼 Asia/Seoul 기준 매시 `:17`에 실행한다.
2. 각 덤프는 먼저 `.partial` 파일로 작성하고 `pg_restore -l` 검사 후 최종 파일명으로 원자적으로 공개한다.
3. 최종 덤프마다 SHA-256 체크섬을 만들고 체크섬 자체도 즉시 검증한 뒤 공개한다.
4. 보존 개수를 최근 5개에서 최근 48개 시간별 복구 지점(약 2일)으로 늘린다.
5. 2시간 이상 남아 있는 중단된 덤프/체크섬 partial 파일을 자동 정리한다.
6. `wdmvp-recovery-refresh`는 더 이상 별도의 임시 덤프를 만들지 않는다. 실제 백업 디렉터리를 읽기 전용으로 마운트하고, 가장 최신의 저장 백업을 선택하여 최신성 확인 → SHA-256 검증 → `pg_restore -l` 검사 → `moneyverse_recovery` 전체 복원 → `SELECT 1` 확인까지 수행한다.

## 안전 조건

- 백업과 복구 CronJob 모두 `concurrencyPolicy: Forbid`를 유지한다.
- `pg_dump` 및 `pg_restore -l`이 성공하기 전에는 최종 백업 파일명으로 공개하지 않는다.
- 복구 CronJob은 백업 저장 경로를 읽기 전용으로 마운트한다.
- 최신 백업이 2시간보다 오래되면 복구 검증 작업을 실패 처리한다.
- 데이터베이스 덤프나 실제 DB 데이터는 Git에 커밋하지 않는다.
- 새로운 평문 자격증명은 Git에 추가하지 않고 기존 Kubernetes Secret 참조를 재사용한다.

## 운영 반영 전 필수 검증

- Kustomize로 `apps/wdmvp` 전체를 렌더링하고 두 CronJob의 매니페스트가 유효한지 확인한다.
- 테스트 환경 또는 비운영 namespace에 브랜치 매니페스트를 적용한다.
- 백업 Job을 수동 1회 실행하여 `.dump`와 대응하는 `.sha256` 파일 생성 여부를 확인한다.
- 복구 검증 Job을 수동 1회 실행하여 체크섬 검증, `pg_restore -l`, 전체 복원, `SELECT 1` 성공을 확인한다.
- 두 Job 실행 중 백엔드 서비스가 정상 상태를 유지하는지 확인한다.
- 위 검증이 끝나기 전까지 운영 `main`에는 병합하지 않는다.
